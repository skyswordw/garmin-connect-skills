# 解读原则与来源语义

睡眠日期为起床日；睡眠时长是秒，HRV 为毫秒，静息心率为 bpm。压力、Body Battery、准备度保留 Garmin 指标含义，分数本身不证明疾病或适合某种强度。body_battery 的 charged/drained 是累计变化量，不当作当天最高/最低值。

跑步距离为米，duration_seconds 为 Garmin 计时时长，moving_seconds 为移动时长，二者不可混用。需要平均配速时用有效距离和对应时长计算；多次活动不要直接平均每次配速。缺数值时保留未知，部分分页只能描述已确认记录或下界。

训练状态来自 mostRecentTrainingStatus，可能早于查询日；引用 observed_date。未知的 Garmin 状态代码保持原代码，不自行翻译为“过度训练”。个人基线至少说明范围和有效样本数；没有足够历史记录时，避免把一周起伏当趋势。

计划来源分为 phased、旧 Coach/adaptive、新 ATP；REST 列表空不足以排除 Coach。日程按 calendarDate 获取，不根据一条任务猜整个窗口覆盖。原窗口内无任务、休息日、无计划、未知家族、接口失败分开描述。自适应计划可能事后修改，报告描述截至抓取时可见的安排。

任务详情保留 workoutSegments/steps 的条件、目标类型和数值。Garmin 的已知 time 条件用秒、distance 用米；pace.zone 目标在已确认的该 API 结构中为速度 m/s，转 min/km 时使用 `1000/(60*v)` 并说明转换。未知目标、条件或单位保持源值，不猜。只有明确给出重复次数和每段结构时才讨论总量；不能把估计时长当完整含热身/间歇的时长。

推荐表达顺序：

1. 事实：哪些日期发生了什么，引用 summary ID 或报告内来源链接。
2. 解释：哪些观察可能有关、哪些还不能判断，考虑缺失、同步和主观体感。
3. 建议：给少量保守选项及观察条件，不强制目标、不自动改训练计划。

如果活动失败但恢复指标有效，只分析恢复并说明跑步量未知；准备度缺失时不阻断有效睡眠分析。事实版周报没有“未见风险”的默认结论；也不因一个低分就给医疗判断或激进补训建议。
