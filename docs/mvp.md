# 首版范围、验收与开发顺序

日期：2026-10-08。设计依据见 [decisions.md](decisions.md) 和 [research.md](research.md)。后续已获授权实现本地 alpha；本文件保留首版验收规范，实际安装见 [README](../README.md)，线上未验证项见 [compatibility.md](compatibility.md)。

## 1. 最小使用闭环

**安装 → 本地认证 → 按需获取 → 轻量摘要 → 独立查询或中文周报。** 先服务自己的 CN 账号与 macOS 日常使用，再以相同流程给群友试用。既有工作区只作为经验与源码白名单来源，不作运行时前提。

| 用户任务 | 最小数据 | 交付结果 |
| --- | --- | --- |
| 看昨晚睡眠、今天恢复 | 睡眠、HRV、静息心率；问题需要时再取压力、Body Battery、准备度/状态 | 事实摘要、相对个人近期记录的解释、缺失说明；不请求活动详情 |
| 看最近跑步是否与恢复匹配 | 日期范围内跑步列表/摘要 + 对应日恢复指标 | 次数/量/时长、可核对的变化与保守建议；不拉圈段/轨迹 |
| 看近期 Garmin Coach 要做什么 | 活跃计划元数据与近期日程，必要时读取选中任务详情 | 计划家族、任务日期/类型/目标、休息日、未识别项；不写入或修改训练 |
| 生成上个完整星期周报 | 同范围日健康、跑步与相关计划窗口，优先复用摘要 | 来源与范围可核对的中文 Markdown；部分缺失仍可生成 |

没有恢复数据也能分析已确认的跑步；活动不可用也能描述有效恢复数据。问题不需要的输入记 not_requested，不自动补全所有指标。首次缺乏个人基线只给描述与限制，用户目标可稍后提供，不是安装条件。

## 2. 安装与首次使用设计

以下入口已实现；完整参数以 CLI `--help` 为准：

| 入口 | 职责 |
| --- | --- |
| garmin-skills auth login / status | 设置或选择 profile、区域、时区；本地密码/MFA；检查 token 是否可用 |
| garmin-skills fetch daily --metrics … | 指定指标和日期，优先缓存，只补缺少或过期项 |
| garmin-skills fetch runs | 指定日期的跑步摘要；分页/覆盖状态明确 |
| garmin-skills fetch plan | 指定近期窗口的计划与任务摘要 |
| garmin-skills fetch workout ID --date DAY | 按需读取一个任务目标/步骤，不下载 FIT |
| garmin-skills report weekly | 校验输入、聚合事实、生成防覆盖中文报告；Agent 可基于它补解释与建议 |
| garmin-skills doctor | 本地环境与档案排错；联网验证使用 auth status --check，输出脱敏 |

开发与首批试用使用固定版本源码和 `uv sync --locked` / `uv run --locked`，项目目录放在笔记库外。面向普通用户交付固定版本包的 `uv tool install` 路径；单独验证其实际依赖解析，不能声称仓库 uv.lock 会自动约束 tool install。尚未发布包时只文档化已测试的源码安装，不给不存在的安装地址。

主 Skill 安装到 Agent 支持的 Skill 目录，调用同一本地 CLI；Skill 与工具版本需声明兼容关系。至少完成一个实际 Agent 的安装、发现、执行验证，其他 Agent 仅列目录规范兼容预期，不默认宣称已测。

首次流程控制在：检查 uv/Python → 安装固定版本 → 本地登录 → 单日少量指标查询 → 打开摘要。区域必须明确，时区优先可靠的系统 IANA 识别，识别失败再询问；有一个账号时不用手写 profile ID、环境变量或笔记目录。全程不要求关闭 MFA、提供 API key、配置数据库或后台任务。

## 3. 首版数据与输出契约

### 3.1 每份摘要必须具备的证据

| 类别 | 必要内容 |
| --- | --- |
| 版本与来源 | schema_version、provider 与精确版本、逻辑获取方法、稳定摘要 ID/内容 hash |
| 隔离 | 不含身份的 profile_id、region、IANA timezone；本地 token 有账号绑定验证 |
| 时间 | requested_range、实际覆盖/缺口、fetched_at UTC、指标所属日期/任务日期；需要时包含观察时间 |
| 结果 | 每指标/数据集 status、规范化值/单位、missing/unsupported/error 原因；活动分页 complete 标识 |
| 获取状态 | 最近成功来源与最近失败尝试分开；整体 partial 可由逐项结果派生，不能覆盖逐项状态 |

使用固定字段白名单，不保留姓名、邮箱、原始 profile、响应头或整段原 API payload。活动 ID/任务 ID 仅在核对来源需要时保留；不输出包含凭据的 URL。源 JSON 经过最小化处理后才进入 Agent 上下文。

### 3.2 状态不能互换

| 状态 | 含义 | 允许的报告表达 |
| --- | --- | --- |
| ok | 有效结构、符合身份与日期，存在相应数据 | 给出数值及来源；真正的 0 可保留 |
| empty | 成功、完整查询后确认没有记录；适用于活动/任务等集合 | “该范围确认无跑步记录”；只有此时完整次数可为 0 |
| missing | 合法响应但该指标未提供/尚未同步，或该日期没有该项记录 | “未提供/待同步”；不把 null 变 0 |
| unsupported | 设备、账号、计划家族或接口明确不支持 | 说明不支持项与已知范围 |
| error | 认证、429、网络、异常结构、覆盖不符等失败 | “无法获取/输入不适用”；列安全错误码与下一步 |
| not_requested | 问题不需要该数据 | 不作结论；不自动发请求 |

旧格式没有必需的身份/status/时效元数据时，明确不兼容，不猜测补齐。异常 list/dict、字段类型或全空预期指标不能算作成功零值；同时对文档允许的 null 与单位变体做有证据的兼容，不见 null 就判整个接口故障。

### 3.3 日期、缓存和计划

- 所有日期范围两端包含，默认周报为用户时区的上一个完整周一至周日，报告写明具体日期。睡眠按起床日，跨午夜活动按已确认的 Garmin 本地日期语义；跨时区或夏令时不依赖服务器 UTC 的 today。
- JSON 摘要与轻量 manifest 即可；成功摘要不可变、失败另记。缓存键含 profile/region/timezone/schema/数据种类/日期或窗口。token 使用平台状态目录、摘要保存在同一状态根内的独立 objects/index，环境和所有持久状态均在笔记库外。
- 初始新鲜度策略建议：今天及最近 3 个已结束日期的健康/活动 1 小时，更早日期 7 天，计划日程 15 分钟；范围查询采用所含日期中最短有效期，empty/missing 的否定缓存至多 1 小时。它们是待试用调整的缓存政策，不保证设备已同步，也不把结束日视为永不变化。显式 refresh 绕过缓存；离线/接受过期时输出 fetched_at 与 stale。周报范围查询必须证明整个范围有缓存覆盖，不能凭已有几条活动推定完整。
- 新请求失败但有旧成功值时，允许带“旧值，截至某时；本次更新失败”的分析；状态分别保留，不能将旧值伪装成本次成功。fresh、有效范围与完整覆盖是不同条件。
- 首版计划默认近期窗口为今天起 14 天；周报取报告周的任务窗口。日程/详情范围受同样的 profile、region、时间与状态校验。当前可见日程不证明历史安排未被自适应修改，需标“截至抓取时”；有同期摘要时再对照。
- phased、旧 Coach/adaptive、新 ATP 三家族设离线 fixtures；必要时采用 GraphQL + fbt-adaptive 详情。窗口无任务、休息日、未加入计划与失败分别测试。REST 空列表与 GraphQL 失败组合时，结论是无法确认，不能显示无计划。自己的实际 CN Coach/adaptive 家族必须在试用门槛内验证，其余尚无账号验证的家族标实验性。

### 3.4 认证、重试与排错

获取流程先检查本地 profile 与 token，只对明确可刷新状态刷新一次。需密码/MFA 时中止非交互查询，让用户运行登录命令；MFA 错码可在本地登录流程有限重试，取消/超时保留原成功凭据。网络故障、403、429 各自分类，403 不一律认定密码错误。

普通数据查询默认顺序执行；关闭或统一接管库内自动重试，防止层层叠加。网络/5xx 首次失败最多一次短重试，超过总请求/时间预算则停止该批；401 刷新后仅重试原请求一次，再失败停止。429 立即停止该 profile 批次，不后台等待并继续；记录 Retry-After 秒数或 HTTP-date 的冷却时间，之后需用户再发起。登录链路同样计入真实传输预算，验证范围包含库内部策略切换，不能只数我们调用的方法。

安全错误码至少区分 AUTH_REQUIRED、AUTH_FAILED、RATE_LIMITED、NETWORK_ERROR、INVALID_RESPONSE、INPUT_MISMATCH、UNSUPPORTED。给出重试/检查区域时区/重新登录等对应下一步，不打印原 str(exception)、认证响应、token、密码、MFA 或私人绝对路径。调试日志同样使用白名单字段。

### 3.5 中文周报与独立输出

报告包含：区域/profile 别名、时区、具体范围、生成时间与输入截至时间；跑步事实和逐日恢复摘要；计划任务及窗口；覆盖天数/样本数/缺失表；来源相对引用与 hash。先呈现事实，再将 Agent 的解释、建议和不确定性独立成段。CLI 单独使用时交付事实版，不伪装已由模型分析。

活动抓取失败时次数、距离、时长显示未知；部分分页只能列已确认活动或下界，不能写成完整统计。缺准备度不阻断有效睡眠分析，计划失败不阻断跑步统计；身份/区域不匹配的输入被拒绝，报告只使用其余可验证输入并说明范围。没有个人基线时不输出统一配速强度判断、精确训练处方或“未见风险”。

同 profile/region/周的报告默认不覆盖；主动修订生成新 revision，发布中断保持原报告。导出 Markdown 可配套携带最小来源摘要/manifest，离开原机器仍能核对，不能要求收件人使用 Obsidian。分享哪些健康摘要由用户决定，不自动上传或发布。

## 4. 离线验收：优先覆盖会改变结论的行为

全部使用虚构输入与 fake transport；测试不得访问用户目录、真实账号、健康记录或网络。通用正常路径之外，至少包括：

| ID | 情境 | 必须满足的断言 |
| --- | --- | --- |
| A01 | 成功空活动 vs 失败 JSON vs 非 list 响应 | 只有完整空查询可输出 0；失败与异常结构为未知；覆盖旧缺陷 |
| A02 | 正常 0、可选 null、无字段、错误类型、全空响应 | 保留 0；按允许结构区分 missing/error；无虚假数值或训练结论 |
| A03 | 同邮箱 CN/global、两个 profile、错账号 token | 状态目录、查找键、摘要、报告不冲突；身份错配中止；不串数据 |
| A04 | 范围空洞、旧 schema、过期、DST/跨午夜、系统 UTC | 不以文件名/mtime 推断覆盖；显示具体范围/时区/时效；睡眠日期正确 |
| A05 | cache 命中、部分命中、refresh 失败、活动分页失败 | 命中不联网；仅补缺；保留旧成功值并标更新失败；不作完整统计 |
| A06 | token 有效、过期可刷新、失效、MFA 错码/取消/超时 | 刷新最多一次；非交互不问密码；有界 MFA 重试；原 token 不被损坏 |
| A07 | 401、403、429、Retry-After 两种格式、超时/5xx | 统计实际传输含库内部重试；限流/认证失败后无批量洪泛；错误不混淆 |
| A08 | 三计划家族、REST 空但有 ATP、详情失败、休息日、未知语法 | 不误判无计划；保留家族/日期/目标；不编造 workout 内容 |
| A09 | 计划跨区/错 profile/过期/窗口不符/ok=false | 与健康/活动同等校验；无法确认计划时其余有效分析继续；覆盖旧缺陷 |
| A10 | 各输入部分可用、全失败、重复生成、写入中断 | 缺失矩阵与来源完整；全失败不产貌似有效周报；默认防覆盖/原子保全 |
| A11 | 注入 token/password/MFA/响应头/绝对路径到异常 | stdout/stderr/JSON/报告/日志无泄露；脱敏不是只过滤正常结果 |
| A12 | 导出、来源 hash、摘要清理 | 引用可解析、变更可识别；被引用成功摘要不会无声清理 |

测试应针对合同和可见行为，不逐行镜像实现。无新变更或未解风险时不反复扩大测试；离线通过仍不能写成线上可用。

## 5. 真实使用与安装验收

本轮禁止登录；下列为后续用户授权并在本地输入凭据时执行的检查。先做少量、只读请求，不用全量同步代替验证：

1. macOS 干净环境按说明安装；CN 首次登录、MFA、本地 token 复用、单日查询成功。真实 token 恢复优先验证自然到期/用户同意的可恢复测试，不破坏唯一凭据。
2. 与用户自己看到的 Garmin 页面核对日期、单位、跑步记录和近期 Coach/adaptive 任务；只记录验证项目/结果，不提交截图、身份或健康数据。
3. 连续两周实际查询与周报，观察同步延迟、摘要复用、缺失解释、重复报告行为；确认无需每次抓取全部接口和手改文件。
4. 至少一位试用者在独立环境完成安装、首次登录、查询，并根据文档处理一个可控错误；未经对应验证的 OS/区域标实验性。
5. 主 Skill 在实际 Agent 中从自然语言正确选择数据集、展示来源和限制，不要求用户理解内部维护命令；纯 CLI 同样可用。

MVP 不能仅凭离线测试宣布完成。支持声明按平台、区域、计划家族分别记录：文档/源码/离线测试/实机验证日期及版本；未覆盖项保留未知，不借用其他项目的成功宣称。

## 6. 开发阶段与停止条件

| 阶段 | 工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：契约与认证资格验证 | 虚构 fixtures；profile/region/日期契约；0.3.6 与 0.3.17 比较；脱敏、持久化、实际请求预算 | 选定精确依赖；离线认证边界通过；CN 少量真实登录/MFA/复用验证。真实验证未授权时继续独立离线工作，不声称已通过 |
| B：按需摘要 | 日健康与跑步、分页、JSON cache/manifest；本地查询 | A01–A07/A11 相关门槛通过；空与失败、混区、过期、缓存均可核对 |
| C：近期计划 | 家族分派、REST/GraphQL、任务摘要与描述限制 | A08–A09；自己的 CN 计划日程核对；其余家族/区域明确实测边界 |
| D：输出与用户闭环 | 中文事实周报、一个主 Skill、固定版本安装与错误恢复文档 | A10–A12；一次完整安装→认证→查询→周报；CLI 独立可用 |
| E：持续试用与小范围分发 | 两周自用、独立环境验证、支持矩阵、许可与依赖署名 | 上述真实验收通过；经明确发布指令才公开发布/推送 |

这些阶段是验证门槛，未授权的真实账号操作不阻塞独立离线实现。阶段 A 的认证问题不能用 macOS 私有脚本默认兜底后宣称跨平台完成。阶段 C 若 CN 新 ATP 仍无法核对，应保留实验性并定位接口，不把普通计划成功替代 Coach 验收。这样可以继续完成其他独立工作，但不能把原核心需求静默删除。

当前 A–D 的本地代码、命令、主 Skill 与离线验收已落地，E 的真实账号、持续自用、独立环境和发布验证尚未完成。计划日程按每个 calendarDate 获取；REST 只查询与窗口相交的候选，详情上限 3 个。最新依赖、网络保护的适配边界单独记录于 compatibility。

## 7. 首版之后再考虑

可选目录导出已实现；进一步的 Obsidian 格式适配按实际需求再做。后续优先顺序：根据群友需求补 Windows/global 与更多计划家族实测 → 成功摘要保留/归档 → 有具体需求再增加其他运动或更深活动细节。

暂不建设网页、托管服务、定时同步、复杂数据库、MCP 服务、全历史归档、轨迹/圈段默认下载或训练处方写入；也不引入额外付费模型。遇到这些需求时先比较现成工具，必要时连接它们，避免让所有用户承担维护和配置成本。
