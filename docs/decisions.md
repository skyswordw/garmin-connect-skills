# 技术路线与复用决策

日期：2026-10-08。依据见 [research.md](research.md)，范围与验收见 [mvp.md](mvp.md)。用户后续授权实现、升级当前最新依赖并以中国区为主目标；现已形成本地 alpha，线上支持状态另见 [compatibility.md](compatibility.md)。

## 1. 推荐结论

继续维护独立仓库，采用 **python-garminconnect + 薄本地工具 + 一个主 Skill**。复用社区的认证和 API 接入；我们维护轻量数据契约、按需获取、失败语义、计划任务解释和中文周报。选择性迁移旧实现的纯摘要函数与防护经验，不整包搬迁，也不自行重写 Garmin SDK。

仓库的价值在于让日常分析可信、可重复、可独立安装。指标获取、中文输出、Markdown、Skill 本身均已有实现，不构成另造一套接入工具的理由。如果以后现成工具满足区域隔离、摘要契约和 Coach 等门槛，可以替换底层；首版不为此建设多 provider 框架。

## 2. 现成方案能满足多少需求

没有证据支持“某项目已满足 80%”这样的精确比例。应区分有接口与用户能完成整个流程：

| 我们的需求 | 已有能力 | 仍需承担的工作 |
| --- | --- | --- |
| CN 登录、MFA、token 恢复 | python-garminconnect 有区域化认证、MFA 与刷新；gccli 有现代登录 CLI | CN 实测、profile/region 强制隔离、认证故障分类及有界请求 |
| 健康与跑步轻量摘要 | 库已覆盖主要指标；多个项目有摘要示例 | 字段白名单、单位/日期、可选缺失与失败区分、分页完整性 |
| 按问题获取 | 库按方法调用、gccli/部分 Skill 按命令查询 | 问题到最小数据集的路由、摘要复用和新鲜度校验 |
| 跑步与恢复结合分析 | 多个中文 Skill 有工作流 | 事实、解释、建议分开；个人基线与限制；去除固定目标和通用配速结论 |
| Coach / adaptive 近期任务 | 库有不同 REST 详情；Taxuspt 有 GraphQL 日程与 UUID 任务路线 | 计划家族分派、CN 验证、任务窗口/元数据/状态一致校验 |
| 可核对中文周报 | 旧实现有报告、防覆盖与部分来源校验 | 修复失败当零、计划混用；增加身份、时效、覆盖与缺失说明 |
| 独立输出、可选 Obsidian | CLI/Markdown 路线已通用 | 默认目录与笔记库解耦；显式导出即可 |
| 普通用户安装和排错 | gccli 安装与 Skill 组织值得参考 | 固定版本安装、首次查询、中文恢复指引、独立机器验证 |

结论：底层接口大多已有，不应重写；尚无本轮检查到的单个项目可以直接交付这八项的可靠闭环。认证、计划和失败语义是关键缺口，不靠增加工具数量解决。

## 3. 为什么选 Python，而非直接采用 gccli / MCP / 归档工具

| 路线 | 实际收益 | 为满足本需求新增的成本 | 决策 |
| --- | --- | --- | --- |
| python-garminconnect 薄包装 | 已有 Python/uv 使用经验；指标与计划接口较全；MIT；可复用旧纯函数和测试经验 | Python ≥3.12、curl_cffi 安装；自管摘要/cache/CLI；必须验证认证边界 | 首选 |
| gccli 直接采用 | Go 二进制安装、终端/浏览器 MFA、OS keyring、现成 Skill | 当前 CN DI 固定 .com、同邮箱跨区 token 键冲突、adaptive 缺口；JSON 为原 payload，仍需摘要层 | 保留为最强替代候选，不作首版依赖 |
| gccli + Python 摘要器 | 可沿用 Python 报告同时借用 CLI | Go/Python 两套发布、版本与错误映射；上述 CN/计划缺口仍在 | 首版收益不足 |
| 整体迁移旧脚本 | 最快得到表面可运行的日报/周报 | 已复现失败当零、计划校验缺口；macOS 私有登录、23 接口/日、个人约定继续被继承 | 只迁移白名单函数与防护 |
| 整体采用 MCP | 已有工具发现、summary 与部分 Coach 接入 | 常驻/stdio 服务配置、工具面与依赖；未免除同样的认证和数据校验 | 暂不建设；Taxuspt 作为计划接入参考 |
| GarminDB / givemydata | 长期数据所有权、增量归档与历史查询 | SQL schema、浏览器或 FIT/raw JSON、长期数据维护；GPL/AGPL 复用义务 | 不是默认摘要路径 |
| 自写 OAuth/DI | 完全控制认证 | 追踪票据、client_id、指纹与地区差异；garth 弃用已显示维护成本 | 不选 |

gccli 的缺口是所查 commit 的源码证据，不是我们真实账号故障复现。若后续修复 CN DI、token 键、adaptive，并有相关实测/回归证据，再用同一验收集比较；不因为语言或现有脚本而永久锁死选型。

## 4. 依赖与版本门槛

- 旧锁定 garminconnect **0.3.6** 保留为调研基线，源工作区未改动。用户授权新项目选择当前最新稳定发行后，重新查询 PyPI/release，均为 **0.3.17**，已精确 pin 并生成新 uv.lock。
- 采用新版同时有 token 原子写入、链接读取防护和认证恢复等具体改进依据。0.3.10 的 MFA 回归不归咎于 0.3.6；离线验证通过不等于新版 CN 线上已验证。
- Python ≥3.12、uv；CLI、JSON、聚合和文件操作使用标准库，platformdirs 选择系统状态目录，filelock 串行同 profile，tzdata 提供 IANA 时区。未迁入 pandas/rich。
- 本地工具不增加模型 API、天气服务、托管同步或额外账号。Agent 使用用户现有推理环境；开发所用 GPT 6.1 Sol 不成为运行时依赖。

风险门槛：库的 API 重试与登录策略是两层逻辑。0.3.17 登录遇 429 后仍可能换认证策略/指纹。已实现同步请求 scope 兼容层，拦截真实 HTTP 请求并在 429 处逃离上游 fallback；安装的上游登录逻辑配合 fake transport 验证了首个 429 只发一次请求。该兼容层需要升级时复测，不作多线程嵌入库承诺。JWT-only 结果的持久化限制、真实 CN 认证和计划仍有未验证项，详见 compatibility。

## 5. 主 Skill 与本地工具的分工

只提供一个面向用户的主 Skill，按问题加载 references：登录排错、恢复分析、近期计划、中文周报。Skill 调用确定性 CLI，消费规范化摘要；CLI 不生成依赖付费模型的解释。

本地工具承担认证、日期/身份校验、请求预算、摘要、缓存、统计与事实报告。Skill 承担最小数据集选择、解释与建议，明确标注推断及限制。用户不使用 Agent 也能得到 JSON 或中文 Markdown 事实摘要。

维护者的依赖升级、源码审查、兼容性验证写入开发文档，不作为普通用户需安装的第二个 Skill。旧 data-builder / running-analysis 的职责可保留在内部模块，不继承它们的目录、训练目标和维护审批流程。

## 6. 必须由代码保证的边界

**身份与目录。** 首次设置创建不含邮箱的 profile ID，显式选择 cn/global；单账号用户自动使用该 profile。token、摘要、缓存索引、报告路径与查找键均包含 profile+region，不能只靠文件名前缀或提示词隔离。认证后的最小身份信息只在本地用于绑定校验，不写入共享摘要。错账号 token 中止并指向对应 profile 重新登录。

**本地认证。** 密码和 MFA 在终端隐蔽输入，不进 argv、聊天、配置或日志。普通获取命令非交互；需要重新认证时返回 AUTH_REQUIRED，不能在批量中途索取密码。可用 token 优先、刷新至多一次；网络/限流不等于密码错误。只有成功且校验通过的新 token 才原子替换旧 token，不自动清空所有账号。类 Unix 权限与 Windows 文件访问限制分别验证，不把 chmod 当 Windows 保护。token 本地限制访问，不宣传为已加密存储。

**数据契约。** 日健康、活动、计划使用同一来源信封：profile、region、时区、请求范围、实际覆盖、抓取时间、依赖版本、状态、缺失原因和摘要 ID。ok、empty、missing、unsupported、error、not_requested 分开；异常结构归 error，不用 None/[]/0 掩盖。部分成功逐指标记录，真正的零值保留。活动分页不完整时不得报告完整次数/总量。身份/区域错误拒绝该输入，其他已验证输入可独立使用。

**请求与缓存。** 每个问题只选必要接口；先校验本地摘要再联网。顺序小批量请求，避免嵌套重试；认证错误、429 中止该 profile 剩余获取。网络/5xx 只做受预算限制的短重试，未知结构不重试。按 profile/region/时区/指标/日期/schema 缓存，失败尝试不覆盖最近成功摘要。缓存有效期是我们的可配置策略，不是 Garmin 的数据完整性保证；离线/过期输入显式显示截至时间。

**日期。** 区域不决定时区；设置记录 IANA 时区。范围采用当地日历日期、两端包含；fetched_at 使用带时区 UTC 时间。睡眠使用 Garmin 的起床日 calendarDate，活动保留已确认语义的本地/UTC 时间；禁止把类似 epoch 的本地时间字段一律按 UTC 转换。日期覆盖逐指标核对，文件名和 mtime 不是证据。

**计划。** 区分 phased、旧 Coach/adaptive、新 ATP。识别到家族后获取所需 REST/GraphQL 窗口和必要任务详情，不批量探测所有地址。REST 空列表不直接证明没有 Coach；未知家族标 unsupported。休息日、窗口内无任务、未加入计划、抓取失败分别表达。原目标和未知 workout 描述保持可核对，不补写热身、组间恢复、总时长或强度。

**分析与报告。** 统计来自有效摘要，解释与建议分段。活动失败显示“无法确认”，不能写零次；部分页只列已确认活动/下界。计划不可用不阻止有效跑步和恢复分析，但必须说明限制。没有足够基线时只描述变化，不强行使用固定配速、睡眠或压力阈值，不把 Garmin 指标变成诊断或训练处方。

**输出。** 本地轻量 JSON + Markdown，不默认下载轨迹、圈段、FIT/GPX/TCX 或保存原 payload。报告携带来源 ID/相对引用、hash、范围、截至时间和缺失项；默认防覆盖，修订生成新版本，发布原子失败不破坏旧报告。导出时一并带必要轻量来源清单，不能给出无法解析的私人绝对路径。被报告引用的摘要不能被缓存清理无声删除。

## 7. 支持范围与推广方式

| 平台 / 区域 | 首版定位 | 尚需完成 |
| --- | --- | --- |
| macOS + CN | 首个正式支持目标；先用于自己的持续使用 | 干净环境安装、真实登录/MFA/恢复、实际 Coach 任务、连续使用校验 |
| Linux + CN | 首版实验性目标，代码保持可移植 | 独立机器安装、curl_cffi 与终端认证、计划实测；通过后再提升支持级别 |
| macOS/Linux + global | 显式选择的实验性区域；必须同样隔离 | 对应账号完整验证；不能从 CN 结果推定 |
| Windows | 后续验证，不宣传首版完整支持 | uv/依赖、文件权限与原子写、终端输入、认证和日历日期实测 |

当前以上均无本项目线上验证；“目标”不是“已支持”。离线模拟可验证隔离与故障行为，不能替代任何一行的真实兼容性。

默认只有区域和必要的时区设置；多 profile、训练目标、笔记目录都不是首次使用必填。先稳定自己的按需查询和周报，再邀请少量群友按同一安装说明尝试。遇到设备没有某指标应正常降级，不能要求换设备、关闭 MFA 或采用我们的笔记结构。

Obsidian 通过“导出到用户选择目录”的可选动作接入，已实现 `--output`；核心环境、缓存和 token 始终在笔记库外，不改笔记插件、不强制 frontmatter 和文件夹名称。

## 9. 主要风险与需要用户决定的事项

最主要风险仍是 Garmin 非公开认证和计划接口变化、CN 计划缺实测、依赖内部重试及设备字段差异。应以小适配层、定向 fixtures、精确版本和可理解的错误恢复控制成本，不能承诺接口永不失效。

用户接受其他设计取舍后，代码及原创图标采用 MIT，版权标注项目 contributors。本轮没有阻塞性的用户技术选择。真实账号验证需用户届时在本地操作，密码/MFA 不进聊天。后续已获用户明确发布指令，公开 GitHub 仓库及 alpha 预发布版；支持状态仍按实际证据标注。群友若明确需要 Windows/global，可调整验证顺序；现在不要求用户选择数据库、MCP 或模型服务。
